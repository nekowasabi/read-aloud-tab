# Process 100 付録: 統合検証とブラウザー互換確認

この付録は人間向けの背景、選択肢、手動確認、対訳のみを収録する。実行時の正本は `process-100.md` である。

## Why

- 対象Jestを先に実行する理由: 機能契約の局所的な失敗を、全体テストのノイズから分離するため。
- typecheck・lint・両ビルドを全体テストより先に行う理由: 型、静的品質、パッケージングの不備を早く判別するため。
- `npm run test` を最後に行う理由: task_deltaが既存機能へ与えた回帰を最終的に確認するため。
- ChromeとFirefoxを実機で確認する理由: API互換だけでは、Options画面とサービスワーカーの実際のイベント順序を保証できないため。
- `dist/`をコミット対象外にする理由: ビルド生成物であり、リポジトリのソース変更と混在させない既存方針を守るため。

## 選択肢

| 選択肢 | 採否 | 理由 |
|---|---|---|
| 対象Jest→品質検査→全テスト→実機 | 採用 | 局所失敗、品質失敗、回帰、互換性の順に原因を切り分けやすい |
| 全テストだけ実行 | 不採用 | 指定された責務ごとの契約と失敗箇所が不明確になる |
| Chromeだけ実機確認 | 不採用 | Firefoxのイベント・設定画面互換を検証できない |
| `onUpdated`を全更新で自動追加として確認 | 不採用 | 既存タブの再読込・遷移を誤追加する契約違反になる |
| ビルド後の `dist/` をコミット | 不採用 | 生成物をソース変更に含めない既存方針に反する |

## 手動確認

1. Chromeで `dist/chrome`、Firefoxで `dist/firefox/manifest.json` を読み込む。
2. Options画面を開き、checkbox、ラベル、説明文を確認する。
3. checkboxを有効化して画面を再読み込みし、状態が保持されることを確認する。
4. 空の新規タブを開き、時間を置いて通常ページへ遷移し、キューへ一度だけ入ることを確認する。
5. 内部ページ、ignored domain、不正URL、無効化後の新規タブで追加されないことを確認する。
6. 実機のブラウザー名、バージョン、操作、観測結果をP100-VG-04のGoalEvidenceへ記録する。
