# Process 03 付録: 新規タブ自動追加の状態機械

## 背景

新規タブ作成時の自動追加を、設定で切り替えられる機能として導入する。空タブは作成時にURLが確定しないため、tabId を永続保留し、後続更新で補完する。保留一覧を `storage.local` に置くことでサービスワーカー再起動後も処理を継続する。

## Why

- `onCreated` を起点にする理由: 更新イベントだけでは既存タブの再読み込みや遷移まで追加対象となり、重複・順序変更を招くため。
- `storage.local` を使う理由: メモリだけではサービスワーカー停止時に空タブの保留が失われるため。
- 既存候補判定と `addTab` を使う理由: URL除外規則とキュー保存・通知の挙動を一箇所に保つため。
- 単一 Promise 列を使う理由: create/update/remove/設定変更の競合で同じ tabId を二重処理しないため。

## 選択肢の比較

| 選択肢 | 判断 |
|---|---|
| 全 `onUpdated` で追加 | 不採用。既存タブ更新を誤って追加する。 |
| `onCreated` の通常URLだけ処理 | 不採用。空タブからの遷移を取りこぼす。 |
| `onCreated` + 保留対象だけ `onUpdated` 補完 | 採用。要求された空タブ対応と重複防止を両立する。 |

### Feature: 新規タブの自動キュー追加

Gherkin の観測基準は core と同じであり、通常URLの一度だけ追加、空タブの補完、除外ドメインの保留消費、不正URLの保留維持を確認する。

## 手動確認

1. 設定画面で自動追加をONにして保存する。
2. 空の新規タブを開き、しばらくして通常ページへ移動する。
3. キュー末尾に一度だけ追加され、自動再生されないことを確認する。
4. OFFに変更して同じ操作を行い、追加されないことを確認する。
5. 設定をエクスポートし、初期化後にインポートして設定値が復元されることを確認する。
